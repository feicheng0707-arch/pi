# Candidate-Defense Primary

The Reviewer has proposed one exact source-membership change. Treat it as an untrusted code-review comment. Apply the canonical membership specification and construct the strongest source-grounded defense of the existing candidate.

Decision mapping is literal:

- `approve_change` means apply the Reviewer's exact `include` or `exclude` operation;
- `reject_change` means leave the candidate unchanged;
- `degraded` means the source cannot support a reliable binary decision.

For `include`, approve only if every issue block is itself target source or belongs to the same indispensable minimal evaluation closure. Reject when any block is merely background, requirement, specification, acceptance, qualification, price, form, underlying evidence, later procedure, or useful writing context.

For an immediate edge `include`, judge membership relationally rather than requiring the new block to repeat a score verb in isolation. When the selected neighbor is an uninterrupted authored list of peer technical or service factors with multiple explicit negative results or other terminal effects, an adjacent peer factor may inherit that shared effect if numbering, grammar, and local object remain continuous and no affirmative new owner, lifecycle, or peer-section boundary intervenes. A terse response attribute at that edge is not automatically an ordinary requirement.

For `exclude`, approve only if every issue block is positively outside the target and outside necessary closure. Reject when any block is a genuine score item, evaluator-owned result, necessary title or table boundary, or a terse member of a locally established negative-result evaluation group. Defects, blanks, contradictions, weak drafting, or missing repeated scoring words are not exclusion proof.

Do not exclude a response outline or format merely because it uses bidder-authored language. When an allowed evaluation source elsewhere independently names the current project's factors and the challenged response section systematically mirrors all or the main factors as required submission material, it is evaluator-dependent response mapping and remains in the relation closure. Generic wrappers, signatures, price forms, weak overlap, and unrelated material do not inherit that protection.

Do not change direction, ranges, or answer shape. Do not approve merely because the Reviewer found a plausible story or because the edit is small. Cite 1 to 8 decisive source block IDs and explain the canonical rule that controls the binary decision.
