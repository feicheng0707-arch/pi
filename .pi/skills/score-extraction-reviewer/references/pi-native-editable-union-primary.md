# Hypothesis-Aware Terminal Adjudicator

Use the frozen accepted single-prompt contract only for file-role classification, the `owner_section` eligibility gate, and the definition of a valid technical evaluation direction. Its mutation scope, container-first range policy, harmless-width tolerance, isolated-pointer deletion rule, and range output contract are Locator behavior and do not govern final release. Final release requires exact minimum block membership under the closure rules below.

The review universe is only a mechanical output ceiling. Hypotheses A and B are unlabeled, fallible membership reads; agreement, disagreement, continuity, width, and origin are not evidence. Use their difference only to direct adversarial attention. Conceptually begin with an empty answer, then publish the complete source-supported subset, which may match either hypothesis, mix them, or match neither. Retain no universe block without positive support as a target core or minimum necessary authored closure.

Use this release procedure:

1. Partition universe blocks by purchaser-authored owner section, package, lifecycle, table, peer controller, and response-form boundary. Keep only currently applicable pre-award evaluation loci allowed by the frozen `owner_section` gate.
2. Inside each retained locus, require at least one concrete technical/service writing direction with a score, grade, comparison, deduction, pass/fail, rejection, or explicit qualitative evaluation effect. Technical requirements, specifications, mandatory clauses, qualifications, conformity screens, supplier promises, and post-award duties are not evaluation merely because failure is invalid.
3. Retain the minimum complete evaluation container and authored closure. An indivisible mixed table/block remains whole. A direct technical/service allocation or cross-reference inside the same evaluation locus is retained atomically, including each independently written occurrence, without inheriting adjacent business/price references or headings. A technical component/weight reference and a technical scoring-standard reference are distinct authored gateways even when both point to the same table.
4. Preserve only necessary authored closure: the shortest direct heading chain for an immediately retained artifact; a short combined parent plus business/technical child-label bridge that jointly points to one retained mixed evaluation artifact; the minimum controller-to-effect subgroup of one bounded rejection, invalidity, deduction, or grade list containing valid technical/service members; an immediately attached note governing the retained artifact's evaluation evidence, validity, threshold, or consequence; and an alternative-method or formula preamble only when it is uninterrupted immediately before that retained rule. In a sibling list, a generic parent heading belongs to its first immediate child or to the inseparable group, not to a later target sibling. A self-identifying atomic technical reference needs no generic parent heading. A title that immediately owns a preceding qualification, compliance, business, or price artifact belongs to that artifact and cannot jump to a later target sibling.
5. Destructively remove separable qualification, business, pure price, procedure, recommendation, reporting, contract, acceptance, penalty, technical-specification, response-template, unrelated-package, and later lifecycle blocks. A valid target elsewhere does not protect them.

After selecting each detailed target core, run one mandatory relation-support recovery pass. A direct current allocation/cross-reference gateway to that core belongs even when it does not repeat the target or effect. When one short combined parent and its peer business/technical child sequence jointly introduces the same retained mixed artifact, keep the shortest complete parent-through-technical-child bridge, including the intervening business child. This starts at the immediate combined controller: a broader evaluation-procedure heading whose first substantive children are conformity, formality, qualification, negotiation, or another excluded stage cannot cross those children to join a later business/technical subcontroller. Apply this pass equally to A/B-common and one-sided blocks; hypothesis membership changes attention, not the proof standard. The pass cannot cross an indirect relay, independent stage, owner, table, lifecycle, or source gap.

Judge repeated authored occurrences independently, but require a direct role. A retained mixed table does not subsume a later narrative technical-review rule, direct gateway, or bounded shared-effect list. A reference occurrence belongs only when its own text assigns a current technical/service weight/effect or directly points to the retained detailed evaluation artifact; an indirect relay to another summary, preface, or pointer is removable. When one controller and one terminal rejection, invalidity, deduction, grade, or other result bracket a finite list containing concrete technical/service members, retain the minimum complete controller-through-effect subgroup, including intervening non-technical members; do not cherry-pick it and do not discard it merely because another table expresses related criteria.

Return the complete final subset of the review universe. Empty is valid. Submit only canonical block IDs through the terminal tool; no narrative, evidence, ranges, or ledger.
