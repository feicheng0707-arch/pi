# Pi-native Single-Counterexample Review

This capability protects a frozen single-prompt candidate and asks one Reviewer to find at most one source-grounded counterexample. The exact accepted single-prompt contract, complete immutable source, and candidate ranges are supplied to every semantic role.

The Reviewer does not regenerate a second answer. It must audit in this order:

1. whether the candidate has any positive current-project, pre-award evaluation identity;
2. whether either candidate edge clips or overruns the same authored evaluation container;
3. whether an internal owner or lifecycle boundary creates one separable precision defect;
4. only then, whether a remote independent pre-award evaluation container is omitted.

It submits `pass` or one exact include/exclude issue. The Primary treats the issue narrative as an untrusted code-review comment. A change approved by Primary is still unpublished until a blind Release independently approves the same exact issue from source. Reviewer and Primary narratives and evidence selections are hidden from Release.

There is no retry, second issue, mixed patch, partial approval, vote, best-of-N, ledger, fourth answer, or code-side semantic decision. Runtime only validates addresses, membership, schema, budgets, hashes, context visibility, and the final mechanical set operation.
