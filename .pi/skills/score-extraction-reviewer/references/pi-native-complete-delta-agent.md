# Pi-native v55 Orthogonal Complete-Delta Review

Treat the accepted single-prompt candidate as a high-quality but fallible first judgment. Its Prompt hash is provenance, not worker context, and its accepted history is not source evidence. The complete immutable source is the only semantic authority.

The target is purchaser-issued, currently effective pre-award source that evaluates a named technical or service response and can directly drive bid writing. A valid target relation needs all of the following:

1. a current evaluation controller or a valid local authored evaluation group;
2. a named technical or service object, using either intrinsic detail or multiple relationally distinct factors;
3. a terminal score, grade, deduction, comparison, ranking, pass/fail, rejection, or explicit qualitative result;
4. the minimum complete source-address closure needed to understand that relation.

A lowest-price or pass/fail method may still contain valid technical-response standards, major-deviation rules, or rejection criteria, but only when source names concrete technical/service response objects such as a scheme, supply or service organization, transport, after-sales service, personnel/resources, specifications, quality, performance, equipment, or other distinguishable response content. A generic statement that the bid must satisfy requirements, contain no material deviation, or pass qualification/compliance is not enough. The award-method label alone is never enough.

Static supplier status is not a technical/service response object: licenses, certificates, financial condition, prior records, general professional ability, eligibility declarations, and the mere existence of a parameter-response form remain qualification or generic compliance. A generic instruction to state parameter values or satisfy specifications is insufficient unless source names concrete evaluated parameters, performance, content, or response dimensions and connects them to a current evaluation effect.

Pure price, quotation, discount, benchmark-price, abnormal-low-price, price correction, or price-ranking content is never the product target when separately addressable, even if it changes points, causes rejection, or determines the winner. Qualification, generic compliance, procedure, contracting, acceptance, and post-award performance are likewise non-target unless inseparable inside one atomic block that also contains a valid target.

Preserve these general authored relationships without broad-container expansion:

- An explicit, currently effective score-allocation or cross-reference gateway belongs when it assigns technical/service weight or names a technical/service review category and points to an actual included evaluation table or rule. A mixed atomic gateway remains whole when one member forms that relation. A generic method title, total-score label, empty pointer, or future method reference does not qualify by itself.
- A source-written bridge stating that a technical/service review category's detailed content or requirements are in another retained table or rule belongs even when the bridge is text-only and the referenced artifact is a mixed atomic table. If one short parent plus business and technical child labels form one authored combined bridge to that retained artifact, preserve the minimum complete bridge group.
- When one authored controller and terminal effect govern a bounded list that contains named technical/service evaluation members, preserve the minimum complete shared-effect subgroup. Do not extend that subgroup into sibling qualification, procedure, price, administrative, or contract sections.
- An indivisible mixed block is retained whole when any part contains a valid target. That precision debt stops at the block boundary.
- A new sibling owner begins at its own heading, label, package prefix, or table title. A price, business, qualification, procedure, or post-award sibling is excluded from that starting block together with its children unless the starting block is itself necessary closure for a valid target.
- A short title or chapter label is necessary only when it directly identifies, groups, or names an immediately following retained artifact. If its immediate artifact is non-target, it cannot leap over that artifact to borrow target identity elsewhere. If none of its governed children is target, the title is removed too.
- A note immediately following a retained technical/service evaluation artifact belongs only when it directly governs that artifact's scoring evidence, submission, validity, threshold, or consequence. A later note for business, price, generic authenticity, anti-collusion, or unrelated materials starts a separate non-target artifact.
- A contiguous preamble immediately governing a retained target artifact may be necessary context when it establishes the current evaluation method, aggregation formula, score precision, evidence rule, or alternative method for that same artifact. Preserve the minimum governing preamble even if it contains mixed price mechanics. This exception is directional and local: it cannot cross an intervening non-target artifact, cannot protect a later post-target price sibling, and cannot rescue a chapter with no target artifact.
- A future or separately issued detail cannot erase evaluation content already stated in the current source. Repeated source occurrences are judged by their own authored relation rather than semantic deduplication.

The Reviewer performs one candidate-aware adversarial audit and submits one complete alternate membership. An empty candidate may pass; every non-empty candidate must face one complete source-grounded falsification proposal. The Primary receives the mature candidate as Set A and the Reviewer counterproposal as Set B, then adjudicates only their exact difference. Common membership is mechanically locked. Candidate provenance is a product prior for conservative mutation, never source evidence: A-only removals require positive exclusion proof and B-only additions require positive inclusion proof. There is no ledger, retry, vote, best-of-N search, code-side semantic rule, or third free answer.

Never read expected answers, evaluator outputs, case identity, historical runs, or another Agent's answer.
