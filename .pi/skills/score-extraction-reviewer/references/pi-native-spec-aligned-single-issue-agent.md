# Pi-native Specification-Aligned Single-Issue Review

This capability performs residual review of a frozen single-prompt candidate. It does not regenerate a second full answer. All semantic roles share the same canonical membership specification below, but use different adversarial duties.

## Canonical membership specification

The target is purchaser-authored source for the current project's pre-award technical or service evaluation that can directly drive the bid response. Select original source blocks only.

1. Document role and lifecycle
   - A purchaser tender, procurement document, evaluation rule, or current-project scoring appendix may contain target source.
   - A supplier-authored final response, internal operating document, post-award acceptance rule, performance assessment, contract execution rule, or settlement rule is not target source.

2. Evaluation owner
   - Allowed owners are scoring, evaluation, bid review, technical review, service review, comparison, ranking, or pass/fail review for the current award decision.
   - Procurement requirements, technical specifications, service requirements, qualifications, price forms, response templates, contract clauses, acceptance, delivery, and performance management do not become evaluation owners merely because they are important, technical, mandatory, adjacent, or useful for writing.

3. Technical or service target relation
   - A valid relation names a technical or service object, dimension, plan, method, measure, capability, performance, commitment, response attribute, or comparable factor and connects it to an evaluator-owned terminal effect.
   - Terminal effects include points, bands, deductions, comparison, ranking, pass/fail, invalidity, or an explicit qualitative result. Pure supplier drafting actions plus ideals such as complete, reasonable, advanced, detailed, or targeted are response standards, not evaluator-owned effects.
   - Rule defects, blanks, contradictions, unfavorable wording, missing values, or imperfect arithmetic do not remove genuine evaluation source from the target.

4. Local authored evaluation groups
   - In a compact or fragmentary source, a repeated uninterrupted list of named technical or service siblings with explicit negative results, grades, deductions, pass/fail outcomes, or other terminal effects may establish a shared local evaluation relation even when a global heading or repeated scoring verb is absent.
   - Once multiple peers establish that local relation, the uninterrupted authored peer list is the minimal evaluation container. A named technical or service sibling immediately before or after the selected peers remains in that container when numbering, grammar, and evaluated object continue and no affirmative new owner, lifecycle, or peer-section boundary intervenes. Do not require every sibling to repeat a score or evaluator verb.
   - A list containing only supplier actions and positive ideals does not establish this relation.

5. Minimal complete boundary
   - Preserve the smallest complete authored evaluation container: necessary title, group, item, body, score or result, threshold, and textually required reference.
   - Do not extend necessary closure to project background, procurement scope, underlying evidence forms, price or qualification material, award notification, contract negotiation, signature, later acceptance, or performance merely because it is nearby or chronologically related.
   - Atomic mixed blocks may be retained when they cannot be split. Precision debt does not spread to separately addressable siblings.

6. Evaluator-dependent response mapping
   - A response outline or format does not establish an evaluation owner by itself.
   - After an allowed evaluation source has independently established the current project's named technical or service factors, a remote response section belongs to the minimal relation closure when it systematically mirrors all or the main named factors and explicitly requires the bidder to organize or submit the corresponding material.
   - Retain the mirrored factor titles, directory, and necessary local format statements. Generic cover pages, signatures, price forms, weak name overlap, and unrelated response material remain outside.

An empty result is correct when no source closes this relation. Candidate membership, role confidence, prior agreement, and useful writing context are never source evidence.

## Bounded adversarial protocol

The Reviewer may pass or open one exact single-direction membership challenge. The Primary tries to defeat that challenge from source. Only a Primary-approved change reaches an independent Release, which tries to prove the proposed override would regress the candidate. The same exact issue is either applied whole or rejected whole.

There is no retry, vote, best-of-N, second issue, partial approval, free third answer, block ledger, or code-side semantic decision. Runtime only validates addresses, membership direction, schema, budgets, hashes, and the final mechanical set operation.
