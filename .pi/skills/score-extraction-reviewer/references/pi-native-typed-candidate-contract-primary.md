# Candidate-Contract Typed Primary

Treat the typed Reviewer challenge as an untrusted code-review hypothesis. Use the complete immutable source and frozen single-prompt contract to adjudicate only the exact addition and removal ranges. Reviewer proof type, evidence IDs, and role identity are coordinates, not source authority.

Always return `publish` when the supplied source is readable and sufficient for a semantic decision. `publish` does not mean accepting the Reviewer: approve only supported subsets and leave rejected arrays empty. Use `degraded` exclusively when immutable source is missing, truncated, illegible, internally unresolvable, or otherwise prevents a reliable judgment. Never use `degraded` merely to express caution after stating that a change is supported or rejected.

For `missing_valid_evaluator`, actively search the complete candidate for a real current-project pre-award evaluation controller or a valid local result group. Supplier response headings, drafting actions, ordinary requirements, and positive ideals such as complete, reasonable, advanced, or targeted are not evaluation effects. If no valid evaluator relation exists, publish approval of the supported whole-candidate removal.

For `omitted_target_or_required_closure`, approve an addition only when every challenged block is a valid target or indispensable textual closure. At an edge, an uninterrupted peer can share an established local evaluation effect without repeating a score or evaluator verb. Defective, incomplete, weak, unavailable, not provided, zero score, or failed can be terminal results. Numbering jumps and missing intermediate visible items do not establish a boundary.

For `separable_non_target_or_boundary_overrun`, approve removal only across an affirmative new owner, lifecycle, peer section, independent content unit, or container-end boundary. Short wording or absent repeated score language is not enough. Result notification, award notice, contract discussion, signature, legal effect, acceptance, service-period assessment, payment deduction, monetary penalty, and later performance are not necessary chronological closure.

Use canonical addresses literally: numeric ID `N` maps only to range string `段落N`; numbering printed inside source text is never an address. `approved_add_ranges` and `approved_remove_ranges` must be exact subsets of the Reviewer envelope. Both may be empty when the candidate defeats the challenge.
