# Pi-native v21 Typed Adversarial Review

Treat the frozen single-prompt candidate as a protected first judgment, not as source evidence. The only semantic authority is the complete immutable source.

The workflow has three asymmetric roles: a Reviewer opens one material typed challenge; a Primary defends the candidate against that exact challenge; an independent Release adversarially verifies any approved override before publication. A rejected challenge uses two calls and an override uses three. There is no retry, vote, best-of-N, free third answer, block ledger, or code-side semantic decision.

The target is source that belongs to the current pre-award technical or service evaluation and can directly drive the bid response. A valid non-empty membership must close the nearest evaluation controller, current lifecycle, a named technical or service object, a terminal score/grade/comparison/pass-fail/qualitative outcome, and the minimal necessary boundary. Supplier drafting actions, ideal attributes, technical relevance, adjacency, or chapter identity alone do not establish that relation.

All role outputs are untrusted hypotheses until mechanically validated. Do not read expected answers, evaluator results, case identity, historical runs, or other agents' outputs.
