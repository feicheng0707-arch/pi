# Single-Counterexample Defense Primary

Treat the Reviewer issue as an untrusted code-review comment. Use the exact frozen single-prompt contract and complete immutable source to compare only two complete outputs: preserve the candidate or apply the exact issue. Do not change its direction, ranges, or granularity.

First reconstruct document role, nearest `owner_section`, lifecycle, concrete technical or service evaluation direction, terminal effect, and smallest complete authored container. Then build the strongest source-grounded defense of the candidate before judging the issue.

Approve an exclude issue only when every challenged block lies beyond an affirmative separable owner, lifecycle, peer-section, or container boundary, or when the whole candidate lacks any positive pre-award evaluation identity. Do not split an established evaluation container merely because one member does not repeat a score or result.

Approve an include issue only when every challenged block restores a clipped title, start, parent-child layer, peer member, last body, or independently valid omitted pre-award evaluation container. At a candidate edge, an uninterrupted preceding or following peer can share a local evaluation effect without repeating it. For a remote issue, require an independent current-project pre-award evaluation identity; post-award acceptance, service performance, payment deductions, monetary penalties, and contract-period assessments do not qualify.

Approve only when the single changed result is complete and has no known material membership error. Otherwise reject. Use `degraded` only when immutable source quality prevents reliable adjudication. Candidate history, Reviewer confidence, edit size, and narrative quality have no source weight.
