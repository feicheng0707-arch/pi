- 多 block 的报价、计价、结算或费用 subsection 绝不是 categorical carrier。不得先把整个区间总结为 pricing，再只恢复少数代表性例外；必须逐 canonical sibling 扫描，完整保留被价格 children 夹住的施工、服务、临时设施、现场水电等资源取得或自理、人员设备配置、交付及结果义务，并把全部 survivor islands 投影到 S。
- 在四类 hard carrier 外，同一不可分 block 同时包含直接履约义务与费用归属、报价提醒、违约金或其他附带后果时，先剥离附带包装；若仍有实际施工或服务、现场资源取得或自理、临时设施、履约人员配置或变更管理、交付或结果义务，该 block 完整保留，且该 leaf verdict 不得再被父标题、费用附句、provisional selection 或 Witness 方向覆盖。必须逐个同级编号 child 独立执行；reason 必须紧凑列出全部 survivor islands，而不是只写最强一个，但不需要输出被排除 child 的 ledger。只有 source 可按 block 分离时，才排除独立的价格或救济 island。
- 工程量清单、清单编制说明、编制范围或编制依据不是第五类 hard carrier，绝不能建立覆盖整章的 categorical veto。必须在四类载体之外按 child 拆分：“工程量清单编制说明”“编制依据”“计价规则/定额/费用规则”“材料信息价/市场价”“计价软件”及其列举的图纸、施工组织、施工规范、验收规范或标准图集，若实际功能只是说明清单或价格如何编制、计取、组价或校核，属于局部 pricing-basis atom；这些技术名词不能被改写成成交后施工或验收要求。相邻的项目名称、建设地点、工程概况，以及“编制范围”中实际写出的当前项目建设内容、工作包或设备采购范围仍是直接项目事实，必须作为最小 island 保留。存活 child 不能反向保护“工程量清单编制说明/编制依据”等价格 wrapper 标题。
- 对赔偿、索赔、诉讼、损失承担、免责、违约救济或风险转移 island，剥离法律后果；若没有独立实施、提供、配置、交付、维护、修理、更换、纠正、恢复或达到标准的义务，则整个可分离 island 排除。邻接的人员、资源、工期、质量或安全正例不能替它取得 membership。仅在“因违约导致工期延误/质量损失/第三方影响，所以承担责任并赔偿”一类因果损害句中出现结果名词，不会产生独立 result duty；删除违约事件、责任、赔偿、扣款和损失分配后没有 operative predicate 时必须排除。
- legal-event procedure empty remainder：对不可抗力、不能履行、违约、索赔或争议事件后的通知、说明原因、提出解决方案、协商、申请减免或其他法律关系处理程序，剥离该法律事件与救济目的；仅为管理不能履行或法律后果而要求“通知对方、说明原因、提出方案、协商解决”的可分离 island，仍是合同风险/救济程序，必须排除。只有剥离后另有独立要求继续施工、恢复服务、采取应急措施、补救交付或达到可核验项目结果的事实，才保留该独立义务。
- 在四类 hard carrier 外，同一不可分 block 若先明确要求实际施工、服务、质量、安全、验收、缺陷修复或交付结果，再附加责任、费用或返工损失后果，前述 operative duty 使完整 block 保留。反过来，若 block 只假设违约、延误、缺陷、事故或第三方损害已经发生，再规定承担责任、赔偿、扣款或风险分配，它仍是纯法律救济；损害对象与当前项目相关不能替代独立履约谓词。
- 成交前 Stage Owner gate 只在四类 carrier 外运行，且必须先于未来时态和 stripped-remainder 建立；它不能把已成立 hard carrier 内部的低层 subsection 重新解释成独立 Owner。边界完整的投标/响应强制性要求 subsection、强制响应表、人员准入表或最低配置表，如果通过岗位、资格证书、人数、承诺、证明、进场信息或无效响应后果共同定义投标准入/响应比较，则 root、表头和全部 children 整体属于成交前证明/准入内容；即使写人数、岗位、资格和未来进场时间，也不得先剥掉 subsection Owner 再把表内 child 改写成成交后人员投入。只有 source 已证明该 subsection 位于四类 carrier 之外、主要直接治理中标后实际履约资源，且资格/证明只是可安全分离的局部注释时，才进入履约 atom 判断。孤立的证据、承诺或声明提交包装本身仍不足以建立 Stage Owner；在没有边界完整 pre-award module 时，从不可分 block 剥离“提供承诺函/证明/声明”等包装后，若仍有中标后人员互斥、不得兼任、实际投入、资源配置或其他直接履约约束，完整 block 必须保留。只有剥离后仅剩成交前证书、证明或承诺材料提交时才排除。
- 采购/招标方式、评审方法、评分基准和定标程序属于采购评审程序，不因位于需求章节或写明当前项目而保留。
- acquisition_method_gate 必须在最终提交前覆盖每个 selected island：公开/邀请/竞争性谈判/询价等取得方式，综合评审/最低价/打分等评价方式，以及候选人推荐、定标和程序安排，只描述采购人如何采购或评价，不是供应商应交付什么，必须排除。它们不能与紧邻的采购范围、对象或工作包 child 合并保留。
- mixed scope/form heading 不会改变 child 原子边界。父标题即使同时命名“范围、内容、形式/方式”等多个主题，也只可因其真实统领的合格范围/内容 body 获得 heading closure；其下可分离、只陈述采购/招标取得方式或评审方式的 sibling child 仍必须排除。不能因父标题、同组编号、当前项目专属性或前一 sibling 是采购范围而把该方法 child 带回。
- 一个父标题下的每个同级编号、括号编号、小数编号、表格行或功能独立 child 都必须重新判 primary effect。前一 child 是采购范围，不能替后一 child 的采购方式、价格、付款、资格或法律内容取得 membership；地址连续不是语义连续。
- non_fact_shell_closure：对每个只含封面、扉页、目录标签、项目名称标题、空表空壳或外部附件指针的 island，剥离身份/指针后若没有独立动作、参数、数量、范围正文或结果义务，必须排除。项目名称或标识再具体也不是独立 membership。标题只有在 source 结构上紧邻并实际统领 selected body 时才可由 heading closure 保留；物理封面、目录中的同名标题、没有正文的空 heading，以及仅指向未随当前 source 提供的清单/图纸/附件，不得闭合进 final_selected_ranges。
- heading closure 是定向且只向后的。必须先判断标题后续、peer-bounded children 是否存在 selected body/table；只要存在且标题直接命名同一合格主题，就必须闭合标题，正文脱离标题后仍可读不是删除理由。被排除的价格、程序、资格或纯法律 children 不能反向让其 wrapper 标题保留。只有全部后续 children 都被排除时，才对标题自身做 stripped-remainder：自身仍明确工期、范围、数量、参数、动作或结果义务时按独立 atom 判断；自身只是纯主题标签时排除。Heading 不能向前依附于上一组 selected sibling，也不能作为前一 selected island 的尾块、上下文、过渡或完整性标题存活。
- selected_shell_body_closure：若 selected children 前有紧邻、同 Owner、在 peer-bounded source 结构中直接命名其合格采购需求主题的真实标题或表头，必须一并 selected。判据是该 heading 是否真实统领连续合格 children，而不是删掉后每条 child 是否仍勉强可读；同一主题下的项目对象、地点、数量、范围等自描述 children 也不能替代其真实主题 heading。heading closure 是 relational membership：合格 heading 无需自身再包含独立动作、参数或事实，non_fact_shell 不得覆盖已经成立的 closure。可沿连续祖先标题链向上闭合，但只保留自身也直接命名合格需求主题的 headings，并在第一个“编制说明/编制依据”、报价计价、程序资格、法律救济或 hard-carrier wrapper 处停止；“在 wrapper 处停止”只排除该 wrapper 本身，不排除其下第一个直接命名范围、工作包、对象、参数或其他合格主题的窄 heading。excluded wrapper 不得因下级正文存活而带回，但窄 heading 也不得仅因外层 wrapper 被排除而丢失。最终 island 从 wrapper 之下第一个合格 heading 开始；没有合格 heading 时从第一个合格 body 开始。
- nested-heading closure：连续出现的父主题 heading→子主题 heading→合格 body 是一个正常 source hierarchy；若父、子 heading 都直接命名施工/服务、人员、资源、工期、质量、安全、材料、交付、验收、运维或其他合格需求主题，则两级都随 body selected。中间 heading 在下一个子 heading 之前没有普通正文不是“空 wrapper”的证据；heading 本来就可以只承担层级命名。只有某 heading 自身属于明确禁止的 wrapper，或其 peer-bounded 全部 descendant body 都被排除时，才排除该 heading。若 provisional selection 在两个 selected body islands 之间留下的 internal gap 仅由这类合格 heading chain 构成，必须恢复该 gap 并闭合 island。
- heading closure 只给 source-function heading 或表头 relational membership，绝不向普通 body child 传播。编号开头、位于标题之后或统领链中都不能把元说明、过渡句、程序句或其他 body 改写成 heading。合格 heading 与后续合格 body 之间存在可分离的 excluded meta/body child 时，可以跳过该 child 继续闭合 heading，但该 child 自身必须保持 excluded；地址连续和标题完整性都不是带回它的理由。
- outer-wrapper restart：当外层“清单/报价/计价的编制说明、编制依据”或等价 document-function wrapper 被 wrapper-stop 排除后，对其下每个 surviving child subtree 重新启动 heading closure。第一个直接命名合格主题的窄 child heading 可以保留，但 survivor 绝不能反向救回外层 wrapper；同级、同关系的 child headings 必须采用一致 closure 标准。
- wrapper-stop terminal check：对每个最终 selected island 的首 block 单独重做 primary-effect 判断。若它只是“编制说明/编制依据”、报价计价、程序资格、法律救济或 hard-carrier wrapper，而下一层已有可独立理解的合格主题标题/正文，则该 wrapper 必须留在 island 之外；不能以“给后文提供上下文”或“完整标题链”为由带回。
- removable-tail terminal check：对每个最终 selected island 的末 block 单独重做 stripped-remainder。若去掉报价/填报措辞后只剩“另附、详见、见附件/清单/图纸”等外部指针，而前面的 selected body 已独立表达当前项目范围或义务，则该尾块必须留在 island 之外；相邻正文、标题闭合或“说明范围依据”都不能替裸指针建立 membership。只有该不可分尾块自身仍明确当前项目对象、工作包、数量参数、技术事实或履约义务时才可保留。
- 每个单 block run 也必须把自身作为反例测试；项目名称具体、人员表详细或未来履约措辞都不能越过 Owner gate。

标题闭合只允许正向：合格需求标题可以随其合格正文保留；合格 child 不能反向让评分、报价、付款、资格、程序、法律救济、清单/报价编制说明或 hard-carrier wrapper 父标题取得 membership。外部 witness 把多个地址放在同一 challenge 也不会改变原子边界：必须逐 block/功能 child 裁决，可以只接受其中真实 heading 并继续排除同 range 内的元说明或 wrapper。

非空 Candidate 的 AUDIT_UNIVERSE 恰好等于 Candidate 地址，只允许在该 universe 内做 false-positive precision repair；不得把普通 OUT 自行纳入。空 Candidate 的 FALSE_NULL_REVIEW_RANGES 与 AUDIT_UNIVERSE 才机械扩展为完整 source，用于 common-mode false-null 审查。RUN_REGISTRY 是纯 Harness 地址预算：连续地址 islands 不超过 16 个时逐 island 提交；超过时机械折叠为一个 AUDIT_UNIVERSE run。该路由只看 Candidate 是否为空与地址碎片数，绝不表达语义、置信度或答案。最终工具对每个 run 只提交一侧 final_selected_ranges，不提交 excluded side；Harness 机械合并所有 selected，并把每个 run 内未提交的地址视为 excluded。每个 selected island 都必须有 source 中的正向 membership 证明；Candidate 身份、provisional、相邻正例、项目名称具体或普通重复都不能代替证明。调用或合同失败时才整体回退原 Candidate。任何 run selection 都不能跨出自己的 run。

hard_root_claims 是 Finalizer 自己提交的 typed Owner 断言，不是第二套答案，也不会由代码替你判断真假。提交真实 root_block_id 与其后 exclusive peer exit；完全不接触 AUDIT_UNIVERSE 的额外 claim 会记录为 non-executing evidence。最终发布仍由 run_selections 机械并集派生，但 final submission 必须满足严格一致性：任何 selected 地址都不得仍落在任何 hard_root_claim 投影内。不得为了保留 descendant，把已由 source 建立的 exit 收窄到 root 内部低层 subsection。若 selected 地址位于你已承认的 root→first same-or-higher different-function peer exit span，必须取消 selection；只有 source 证明该地址之前真实出现了同级或更高层级、功能不同的 peer，才可据此纠正 exit 或撤回错误 claim。Witness 本身不会形成代码 override。若最终仍相交，Harness 只会判 contract failure，不会替你选择 claim 或 selection。没有真实 root 就不要 claim。

每次提交都严格分两阶段思考，并把两段 reason 作为该次工具参数提交：
Phase 1 owner_reason：先写完整 source 身份，再建立影响 AUDIT_UNIVERSE 的实际 Owner root→semantic-exit 假设。只判断 Owner，不用局部技术价值挖洞。先读 root block 的实际功能，再从 root 向后寻找同级或更高层级的不同 Owner peer；禁止把更早章节、内部附件或技术 child 当 exit。
Phase 2 residual_reason：主动反驳 Phase 1 的过宽/过窄 Owner，并按三个方向完成全局闭合：
1. 非空 Candidate：对完整 Candidate 做全局破坏性精度审查。寻找当前最强 false-positive counterexample，拆出后继续攻击剩余 selected islands，直到再无可安全分离的非 requirement island；同时反向检查每个拟删 island 是否仍有 survivor duty、必要 heading/body/table closure 或 source-fidelity 依赖。reason 只紧凑列出全部 false-positive holes 与 survivor islands，不逐 block 叙述。
2. 空 Candidate：对完整 source 做 common-mode false-null 审查。先检查 hard-carrier root 与 first semantic exit，再在每个非 carrier island 寻找最小 source-proven requirement atoms；不得把 null 当保守默认，也不得因全源较长而跳过 later peer island。
3. 第二轮 reconciliation：先不把 Witness lane 名当作证据，独立重做一次 provisional selected 的最小破坏性精度门：逐 selected island 检查首 block、末 block、singleton 及 source 中有肯定 exclusion predicate 的局部 child；mixed block 剥离包装后仍有当前项目事实或 operative duty 时不得整块排除。在四类 carrier 外，一个 canonical table block 的 row/片段不是独立输出地址；若同表任一 row/片段仍有合格对象、参数、人员、工期、质量、服务或结果事实，必须拒绝任何仅凭其他付款、价格、合同指针等 row 删除整块的 Witness 或 provisional rationale，也不能把语义分析中的逐 row 删除投影成整个 block exclusion。只有整块剥离后 surviving remainder 为零才可排除该 table block。每个 selected 的可分离 remedy tail，包括纯违约金、扣款、赔偿、责任后果或风险分配，都必须在目标 canonical block 自身找到独立 operative predicate 才能保留；前后相邻 block 的施工、供货、质量、修理、纠正或交付谓词不能归给目标 block。若 provisional 或当前 reason 借用了邻块谓词，必须纠正 provenance，并排除自身没有 operative predicate 的纯 remedy block；同一 block 内确有存活 duty 时仍完整保留。随后逐项审查 review packet 中的 hard_claim_selected_ranges、provisional_unclaimed_excluded_ranges、selected_boundary_gaps、independent_semantic_witness、fully/partially selected runs、selected_island_focus 与有界 focus_blocks。Witness 原始 focus 已按 provisional state 与连续 block ID 分为 exclude-scan selected islands 和 select-scan excluded islands；该分组只用于地址导航，不是语义标签或优先级。provisional 全空时，先审查不受任何 provisional hard-root claim 覆盖的 excluded ranges；合法 hard claim 不能解释这些地址，必须独立完成 false-null membership 判断。Witness 是可反驳 counterevidence；exclude/select lane 名和 `overlaps_provisional_hard_claim` 本身都不是修改理由。必须逐 lane 核验 attacked_premise 是否真的由 supporting_block_ids 的原文成立；接受时确认肯定的 membership/exclusion premise，再自行修正 selection 或 claim；反驳时指出相反的具体 premise。若 exclude lane 的唯一理由是目标与别处普通重复、语义冗余、可由相邻内容覆盖或删除后更短/整洁，必须拒绝该 challenge；只有目标 block 自身另有独立、肯定的 exclusion predicate 时才可接受，supporting_block_ids 证明重复本身不能替代该 predicate。对 mixed Witness range 逐 block/功能 child 原子化，不能整 lane 接受或整 lane 拒绝。每个 final hard-root exit 都必须重读 root 到下一 hard root 之间的 source-text chapter/module boundaries；layout inheritance 与 EOF 不是 continuation 真值。

residual_reason 只写固定点攻击后的全部 safely separable false-positive holes、全部 survivor islands、空 Candidate 时的 false-null 召回结论、Witness reconciliation 和最终 compact selected islands；禁止按每个 Candidate range、被排除 child 或章节逐项复述。提交前逐独立 child 在心中完成原子判断，但不输出 exclusion ledger。RUN_REGISTRY 的每个地址 island 都必须在 run_selections 中出现一次，但 reason 不需要逐 run 复述。压缩 ranges 前必须检查：若两个拟 selected 地址之间存在任何已判为元说明、程序、价格、付款、资格、纯法律、hard carrier、non-fact shell、bare external pointer 或其他非 requirement child，必须在该 child 处拆开，不能用一个宽 range 跨过。terminal set gate：先冻结完整语义集合 S，S 必须包含所有已经确认的 heading/body/table closure，并排除全部已确认 holes；不得复制 provisional ranges。每个 run_selections 只能由 `compact(S ∩ run)` 生成。若 reason 已确认某 heading/body selected 但它不在 S，或已确认 hole 却仍在 S，必须在工具调用前纠正。第一轮工具提交是 provisional；第二轮必须吸收机械 review packet，并自行接受、反驳、收窄或撤回 Witness/claim。两轮都必须恰好调用一次 submit_final_selection，禁止 Markdown、可见 prose、thinking 内容、额外工具或伪工具语法。
