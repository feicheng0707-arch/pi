# Pi-native Runtime Contract

本文件只约束 active Pi-native 路线。旧 `reviewer.md` / `release.md` 的两调用 overlay 状态机仅作为 V1 实验基线，不得混入本路线。本文是 Harness/governance 真源并进入 capability hash，但不整篇注入 Finalizer 或 Witness system prompt；模型所需的语义与当轮字段权限由各自 role Prompt、动态 `TERMINAL_CONTRACT` 和 tool/schema 提供。

## 固定执行序列

成功发布路径恰好三次 provider call；失败路径可以提前终止，但任何路径最多三次：

1. 同一个 GLM Finalizer 在完整不可变 source 上提交 provisional `submit_final_selection`；
2. Doubao 2.0 Pro Witness 在一次 assistant response 的唯一 text block 中直接提交严格 JSON counterexample；显式 enabled profile 可另带至多一个不转发、不持久化正文的 thinking block。它读取确定性有界 `REVIEW_FOCUS_SOURCE`，随后读取独立的 `MECHANICAL_TARGET_AUTHORIZATION`、包含 projected/no-projection 两类 claim 的 `PROVISIONAL_HARD_ROOT_CLAIMS`，再读取 `UNTRUSTED_PROVISIONAL_RATIONALE` 下受既有 schema 限长的 provisional `owner_reason` / `residual_reason`。物理与语义执行顺序必须是 source → authorization/typed claims → untrusted rationale → unified enumerate/rank；读完 rationale 前不得生成、淘汰或排序候选。普通 atom 争议前，Witness 先从 source 执行 `denied_local_hard_root` 与 `overbroad_recovery` 两个 rationale Owner falsifier：前者攻击错误否认 local hard root，后者攻击把 recovery 扩张到其 source-bound matching module 之外；统一排序为 `rationale-exposed owner-boundary contradiction > other source-proven root contradiction > typed/rationale/source exact contradiction > strongest singleton falsifier`。Witness 最多提交一张独立 typed Owner span、两张 atom remove 与一张 add，总卡数最多四。Rationale 只作待证伪 claim，不是 source、证据、裁决或 supporting material；source block 不内嵌 provisional state、target permission 或 root projection；authorization 只给 target 地址权限，typed claims 只作待核验 support；
3. 第一步的同一个 Pi Agent loop 在真实 provider 边界构建全新、确定性的 neutral-replay context：完整 source 保持不变，不回放历史 assistant/toolResult 角色或 tool-call ID；Harness 保持同一个 `submit_final_selection` 工具名，但把 provider-visible schema 切换为只接受 `final_delta` 的第二阶段 schema，并在非权威 provisional/review packet 外追加权威 phase marker；Finalizer 提交 sparse `final_delta` 后，Harness 再机械派生 final selection。

无 retry、第四次调用、投票、best-of-N、逐 block ledger 或答案驱动路由。Finalizer stream 在调用边界硬限制为最多两次，首轮无 contract-valid provisional 时立即停止，第二轮结束后无条件停止。每个 Finalizer turn 必须恰好含一个 contract-valid `submit_final_selection`，它是唯一权威输出；同名工具在两次 provider call 中分别绑定 provisional-only 与 final-delta-only schema。Prompt 仍要求不输出 prose；若 provider 同轮附带普通 text，Harness 只对全部 text block 按原顺序无分隔拼接，记录字符数、SHA-256 与 `forwarded=false`，不解析、不解释、不写入 review packet，也不允许影响 provisional、final 或发布。Finalizer trace 只持久化 raw tool arguments、normalized structured submissions 和上述 auxiliary-text 元数据，不持久化 raw Finalizer assistant message；在进入第二次 Finalizer stream 的真实 LLM context 前，Harness 必须机械验证唯一 provisional tool call 与对应 tool result 成对匹配，然后移除历史 assistant/toolResult 角色、tool-call ID 和 auxiliary text，把 normalized provisional 与原 review packet 追加到原始 user 输入。`ACTIVE_FINALIZER_PHASE=final_delta`、`THIS_IS_FINAL_PROVIDER_CALL=1` 和 `HARNESS_PHASE_CONTROL` 位于 `REPLAY_TRUST_BOUNDARY` 之前，属于 Harness 权威执行控制；`REPLAY_TRUST_BOUNDARY` 只把 normalized provisional 与 review packet 的语义内容标记为非权威，不得反向取消 phase。配对异常、空 review packet、Finalizer thinking、未知或额外 tool call、截断、非法 schema 或其他非许可内容均 fail-closed。两次 Finalizer turn 始终关闭 thinking；`owner_reason` 的 schema 硬上限均为 1200 字符。第一轮 provisional `residual_reason` 以 2400 字符为压缩目标、8000 字符为 schema 硬上限；第二轮 final delta `residual_reason` 的 schema 硬上限为 2400 字符。超限字符串必须 contract-fail，Harness 不静默截断语义文本。

Witness 使用 `tools=[]`，provider-visible JSON response 上限 2400 tokens，默认 `thinkingMode=disabled`。只有预先声明的 sealed A/B runner 可以在第一次语义调用前，把整个 run 的 `witnessRuntime.thinkingMode` 明确冻结为 `enabled`；不得按 case、正文、provisional、评测标签、历史结果、provider 返回或失败状态选择或切换。两种 profile 使用相同 Doubao model、source/focus、Witness Prompt、exact JSON schema、调用序列、一次 Witness 上限和 no-retry 合同。provider payload 都设置 `response_format={"type":"json_object"}`，删除 tools、tool choice、parallel tool calls 和 reasoning effort，并明确发送与冻结 profile 一致的 `thinking={"type":"disabled|enabled"}`。Provider-reported hidden reasoning 独立记账并受冻结 profile 的 run reasoning 上限约束，原有 run 总 output 上限也继续生效。Disabled mode 仍只接受恰好一个 JSON text block，任何 thinking block 都 fail-closed；enabled mode 只额外允许至多一个 thinking block，并仍要求恰好一个 stop 正常的 JSON text block。Harness 不读取 thinking 的语义，不把它写入 raw/normalized arguments，不转发给 Finalizer，也不持久化其正文；trace 仅记录 mode、block count、character count 与 `forwarded=false`。对完整 JSON text 仍只执行一次原生 `JSON.parse`，不提取 Markdown、不修补 partial JSON，再用同一 TypeBox exact-shape 校验和三 array/card 交叉字段校验。Witness raw trace 只保存完整 JSON assistant text，只有原生 `JSON.parse` 成功后才记录 normalized parsed object；provider JSON mode 与 enabled thinking 都不替代本地合同，也不提供语义正确性。tool call、prose/Markdown 包裹、多个 text、超过一个 thinking block、异常 content、非法 JSON 或非法 schema 均 fail-closed。开启 thinking 只是一个可归因的 runtime A/B 变量，不构成质量提升结论。

## 地址与权限

- 非空 Candidate 的首版 `AUDIT_UNIVERSE` 等于 Candidate 地址；此路线首先验证 false-positive precision repair，不冒充已经解决任意远端 OUT omission。
- 空 Candidate 为避免静态保留错误 `null`，`AUDIT_UNIVERSE` 机械扩展为完整 source；该路由只依据 Candidate 是否为空，不读取正文、case、标签或评测结果。
- `RUN_REGISTRY` 只按地址连续岛生成；不超过 16 个时逐岛提交，超过时折叠成一个 `AUDIT_UNIVERSE` run。该结构不表达语义或置信度。
- 第一轮 provisional-only schema 必须 `submission_kind=provisional_selection`：每个 run 恰好提交一次 `final_selected_ranges`，`run_deltas` 必填且受 `maxItems=0` 约束。Harness 机械并集为 `S0`；run 内未提交地址视为 provisional excluded。不得提交 excluded ledger。
- 第二轮 final-delta-only schema 必须 `submission_kind=final_delta`：`run_selections` 必填且受 `maxItems=0` 约束，只为实际发生的 atom 或非 Witness-Owner 变化提交 `remove_ranges` / `add_ranges`；每个非空 delta entry 至少一侧有地址。`accepted_owner_boundary_challenge_indices` 必填，允许 0-1 个 stable zero-based index。remove 只能引用该 run 的 provisional-selected 地址，add 只能引用 provisional-excluded 地址；已获双钥匙授权的 Owner span 无需在 remove 中重复枚举。重复 run、重复 block、错误 membership、跨 run、普通 `OUT` spill 或不存在地址全部 fail-closed。accepted array 为空时不产生 Owner 投影；一旦提交 index，它必须引用已授权 challenge，且 final `hard_root_claims` 必须含 `carrier_type + root_block_id + exit_block_id_exclusive` exact match，否则 contract-fail。双钥匙有效时 Harness 机械形成 `A=S0∩[root,exit)`。未提交地址机械保持 `S0`，Harness 唯一执行 `S=(S0-A-Δ-)∪Δ+` 并 compact。
- 第一轮每条 selection range 先按完整 source 校验地址，再与其声明的 run 做最小权限投影。只有投影非空、只形成一个连续授权岛、且额外地址全部是未属于任何其他 run 的普通 `OUT` 时，Harness 才机械丢弃 `OUT` 并记录 `trimmed_out_of_run_ranges`。全 `OUT`、命中其他 run、跨同一 collapsed run 的多个授权岛或引用 source 中不存在的 block 均 fail-closed；Harness 不把它们解释为空选择、拆成多岛或改投其他 run。该 spill 容错不适用于第二轮 delta。
- `hard_root_claims` 只含 carrier type、inclusive root 和 exclusive semantic exit。代码只把 claim 投影到 `AUDIT_UNIVERSE`，不判断 claim 真伪。
- `terminalBlockId` 只取完整 source 最后一个 block 的数值 ID。Finalizer 若把 EOF 写成 `exit_block_id_exclusive = terminalBlockId + 1`，Harness 只把这个 one-past-end 地址表示机械归一化为 `null`；它不读取正文，不证明 hard root 成立或 Owner 延续到 EOF。其他不存在、早于或等于 root 的非法 exit 仍 fail-closed。raw 与 normalized submissions 都进入 trace。

## 严格最终一致性

最终不变量：

```text
FINAL_SELECTION ∩ FINAL_HARD_ROOT_PROJECTION = ∅
```

Witness 只能提供反例，不能单独形成 override、自动删除、自动保留或自动收窄 exit。唯一自动 Owner 投影必须同时具备 Finalizer 显式提交的 Witness owner challenge index，以及 final `hard_root_claims` 中 exact carrier/root/exit；Harness 随后只做确定性的 `S0∩[root,exit)` 集合删除，不读取 `source_conclusion`，也不要求 `run_deltas` 枚举该 span。未接受时不投影；显式 index 未知、只有 index 而无 exact claim、或字段不 exact match时 contract-fail，同样不投影。Finalizer 若接受 Witness 对 claimed address 的 add 反例，仍必须自行收窄或撤销 claim；若保留 claim，则必须自行取消该 selection。第二次提交派生的 final selection仍冲突时 contract-fail，Candidate 原样保留。Harness 不替模型在 claim 与 selection 之间选择。

同一 final root 若提交不同 exit，同样 contract-fail。无投影 claim 只记录为非执行证据；除上述单岛普通 `OUT` 最小权限投影外，越权 ranges、缺 run、重复 run 或非法 schema 均 fail-closed。

## Witness 边界

- Witness schema 固定为三个必填、non-nullable array：`owner_boundary_challenges` 为 0-1 张、`remove_from_provisional` 为 0-2 张、`add_to_provisional` 为 0-1 张，总卡数最多四；空数组精确为 `[]`，不使用 none sentinel。Owner card 恰有 `carrier_type`、`root_block_id`、`exit_block_id_exclusive`、`anchor_block_id`、`source_conclusion`、`supporting_block_ids` 六字段，表达 inclusive root / exclusive exit 的 typed hard-carrier span。remove card 恰有 `kind`、`ranges`、`source_conclusion`、`supporting_block_ids` 四字段且 kind 只能是 `atom_membership`；add card 同为四字段且 kind 可为 `owner_boundary|atom_membership`。singleton range 恰好一个，conclusion 非空白，supporting block 为 1-8 个。direction 由顶层字段机械映射，不由模型提交；字段名、card 数量、card 顺序和 supporting block 数量都没有证据权重。192 字只是 Prompt 压缩目标，不是本地 schema hard gate；整体成本仍由 2400-token 输出上限硬控制。缺字段、`null`、字符串 `"null"`、空对象、额外字段、旧 exclude/select/none/primary/secondary、direction、verdict、attacked_premise 或其他旧 schema 全部 fail-closed，不做兼容归一化。
- JSON parse、turn shape、TypeBox exact shape 和 card 交叉字段必须先作为全局协议完整通过；随后 Harness 在任何逐 card 授权前，先对所有 Owner span/root/exit/anchor、singleton target range 与 supporting ID 做完整 source 地址校验。非法 span/range 或 source 中不存在的 target/support 地址仍使整个 Witness contract-fail，不能降级为 card 弃权。
- Owner card 的 root、非 EOF exit、anchor 与 supporting IDs 必须对应全局 `source_ordered_blocks` 中可见地址；anchor 必须位于 typed span 内、属于 `S0` 与 `AUDIT_UNIVERSE`，root/exit 只提供 source-bounded span 地址，不凭自身授权删除。remove/add card 的唯一 target 必须是 singleton canonical block，并完整属于最终实际序列化的 `MECHANICAL_TARGET_AUTHORIZATION` 对应字段中的一个连续 range，同时属于 `AUDIT_UNIVERSE`；source block 不携带 provisional state 或 target permission。不得跨 group、跨地址 gap、跨字段、覆盖任何未展示 block 或 target universe 外地址。`supporting_block_ids` 只需证明 source 中真实存在的证据 block 已进入全局 `source_ordered_blocks`，不授权 unseen target，也不要求与 target 同 group/universe。若 source 地址真实存在但 span/anchor/target 未获 focus、authorization 或 universe 权限，或 support 未进入全局 focus，Harness 必须拒绝整张原始 card 为 `rejected_source_focus`，不得裁剪、补洞、过滤同向 block、修改 conclusion 或从残余地址生成 challenge。各 array 的其他 card 独立保留：空 array 是 `valid_none`；至少一张 card 获授权时对应 slot 为 `valid_challenge`；非空且全部 card 被拒时为 `rejected_source_focus`。任一卡 rejected 使 overall coverage 为 `partial`；当 Owner slot 不是 `valid_challenge` 且 exclude/select 两个 atom lanes 都是 `rejected_source_focus` 时，overall coverage 才为 `none`。不重试。
- Witness raw trace 记录唯一 assistant text；只有原生 `JSON.parse` 成功后才把 parsed object 记录为 normalized arguments。`structuredTerminal=true` 只表示纯 JSON、TypeBox 和 card 交叉字段合同已全部通过，不表示 source premise 正确或 challenge 被 Finalizer 接受。
- 通过逐 card 授权后的 card 才能进入 provisional hard-claim overlap / non-overlap 分区与 source quote 附加。代码只附原文，不判断 `source_conclusion` 是否成立，也不识别重复、冗余或更短/整洁是否构成 exclusion。
- 每张已授权 remove/add card 的 singleton target 只机械标记是否落入 provisional hard-claim projection；把 `remove_from_provisional` / `add_to_provisional` 固定映射为 internal exclude/select，保留 `card_index`、机械 direction 和 kind，不得拆分或复制 card。每张已授权 Owner card 保留原始 `owner_boundary_challenges` array 中从 0 开始的稳定 index 与 typed span，不得降格、拆分或复制成 remove card。所有 index 在过滤或拒绝后不得重编号。Harness 只能在 Finalizer 双钥匙授权后执行 Owner span 集合投影，不能仅凭 challenge 自动升级为 Owner veto。
- Harness 可附 root、exit、目标原文 quote 及 answer-free layout，但不能生成语义论证、修复方向或结论。所有业务攻击规则只能位于 active Prompt，不得由代码拼接 `attack_contract`。
- Witness 输入必须先序列化 `REVIEW_FOCUS_SOURCE`，再单独序列化 `MECHANICAL_TARGET_AUTHORIZATION` 与 `PROVISIONAL_HARD_ROOT_CLAIMS`，然后才以 `UNTRUSTED_PROVISIONAL_RATIONALE` 原样机械序列化 normalized provisional `owner_reason` / `residual_reason`，最后才允许统一 enumerate/rank。source-first 顺序避免 provisional state/claims/rationale 抢占原文锚点；authorization、typed claims 与 rationale 都不能成为 supporting evidence 的替代品，代码也不得解释 rationale、据其生成攻击方向或根据其语义/内容选择 focus；只可按 rationale serialized length 机械缩减 effective focus budget。
- Harness 可只按 provisional selection、typed hard-root claims 与地址连续性机械生成 `PROVISIONAL_UNCLAIMED_EXCLUDED_RANGES` 和 `SELECTED_BOUNDARY_GAPS`，并分配对应的有界原文 focus。前者只是 `excluded - projected hard-root claims`，后者只包含 selected island 前最多两个 excluded 地址或两个 selected islands 之间最多两个 excluded 地址；两者都不声明 heading、Owner、membership 或修复方向。Harness 必须对 projected 与 no-projection 两类 typed claim 的 root 与非 EOF exit 各机械加入目标地址及前后最多两个实际 source block；只有 projected claim 继续为其 AUDIT_UNIVERSE projection island 加入固定首尾各两个 block，并参与 unclaimed/overlap/最终一致性。全部 focus block 去重后必须在 `source_ordered_blocks` 中按 `block_id` 严格升序且每个 block/正文只出现一次；重复 ID fail-closed。source block 只含地址、answer-free layout、原文和截断标记，不内嵌 target state 或 claim projection。`MECHANICAL_TARGET_AUTHORIZATION.remove_from_provisional|add_to_provisional` 由可见 focus block、AUDIT_UNIVERSE 与 provisional membership 按连续性机械生成，是 singleton target-range 权限；Owner span 另按可见 root/exit/anchor、anchor provisional membership 与 universe 做 typed address authorization。上述字段不生成语义标签、置信度、优先级或修复方向。Harness 始终在全部 selected islands 之间 round-robin，并按每岛确定性的 breadth-first recursive-midpoint 顺序覆盖岛内 block；预算容纳时必须完整展示全部岛内 block。岛内 midpoint 队列耗尽后，再用剩余预算，以 `packet.blocks` 数组的 source-order index 为唯一邻接关系，从每岛首端向前、末端向后逐层 round-robin 外扩 focus；不得用 `blockId ± N` 猜测邻居，也不得按文档先后让早期或长岛耗尽预算。该调度只读取地址集合与 source-order index。
- Witness focus 最多 256 blocks；`REVIEW_FOCUS_SOURCE`、`MECHANICAL_TARGET_AUTHORIZATION` 与 `PROVISIONAL_HARD_ROOT_CLAIMS` 的 nominal 合计序列化上限为 180000 字符，单 block 原文 4000 字符。normalized rationale 另按 UTF-16 code unit 复核既有 1200/8000 上限；每个 code unit 为 JSON 最坏扩张预留 6 字符，并计入固定 object envelope 与 `UNTRUSTED_PROVISIONAL_RATIONALE=` marker，因此 rationale line 的确定性上限为 55272 serialized characters。focus/auth/claims 与实际 rationale line 共享 190000 serialized-character combined budget；effective focus cap 为 `min(180000, 190000 - actual rationale line length)`。这些硬预算不能通过增加调用或语义筛选绕过。回传 Finalizer 的 Witness quotes 总计最多 32000 字符、单 block 2000 字符，selected-island focus 原文总计最多 48000 字符、单 block 2000 字符。provisional 全空时仍覆盖 excluded islands 首尾和固定邻居，不能把空结果当作默认正确。

## 失败与预算

- Finalizer 第一次或第二次 provider/schema/tool/地址权限失败，包括 owner reason 超过 1200 字符、第一轮 residual reason 超过 8000 字符或第二轮 residual reason 超过 2400 字符：Candidate 原样保留，`reviewDegraded=true`。第一轮的 2400 字符仍只是压缩目标；第二轮的 2400 字符是 hard gate。Harness 不截断超限 reason。只有第一轮 provisional 的单岛普通 `OUT` spill 可经机械投影而不失败；第二轮 delta spill 必须拒绝。raw submission、canonical decision、accepted Owner index、自动 Owner 投影、delta 和被裁地址都必须可审计。
- Witness provider、JSON、turn-shape、schema、cross-field、完整 source 地址，或 Owner slot 非 `valid_challenge` 且 exclude/select 两个 atom lanes 均为 `rejected_source_focus`：仍不重试；Finalizer 可完成固定第二次提交用于 trace，但最终不得应用修复，Candidate 原样保留并 degraded。单张 card 的动态 focus/slot/group/universe 授权失败不是完整 Witness failure：其他有效 card 或未形成双 atom-lane 拒绝的 `valid_none` 状态继续进入第三次调用，最终可在 `partial` coverage 下发布。
- 总 provider calls 必须恰好为 `2 Finalizer + 1 Witness` 才可发布；任何第四次调用或角色数量异常均 contract-fail。
- 调用前用 answer-free 确定性上界同时估算 Finalizer 第二轮最坏 context 与 Witness 最坏 context；Witness 上界覆盖 system Prompt、固定 metadata、190000-character combined source/auth/claims+rationale serialized budget、输出与 safety reserve，不能把 9200 raw provisional reason characters 直接冒充 transport 上界。任一冻结模型容量不足都在第一次语义调用前失败关闭。Finalizer 每轮输出上限 8000 tokens，owner reason 硬上限 1200 UTF-16 code units；第一轮 residual reason 目标 2400、硬上限 8000，第二轮 residual reason 硬上限 2400 UTF-16 code units；Witness 2400 tokens。run 总 input/output 上限固定为 720000/20000 tokens；reasoning 上限由调用前冻结的 Witness profile 决定，默认 disabled 为 1000 tokens，显式 enabled 为 6000 tokens。冻结 profile、rationale 输入顺序、55272 provisional rationale serialized bound、190000 combined cap 和 effective focus cap 进入 capability/trace；它们不能在 run 中途切换。
- 单请求 timeout 默认 300 秒，workflow timeout 900 秒。外部 abort 与 workflow timeout 合并为同一 signal，并传入 Finalizer 与 Witness；首次调用前、Witness 前和发布前均检查。取消或超时只允许 preserve Candidate + degraded。

## Harness 边界

代码只负责 Pi Agent harness 和原子机械能力：answer-free packet、SHA、地址范围、结构证据、上下文/调用/Token/超时预算、严格 schema、focus 预算、地址/focus/authorization 校验、双钥匙 Owner span 集合投影、普通集合差异、最终 patch 和 trace。代码不得读取标题或正文含义，不得按关键词、行业、项目、case ID、source hash、历史结果或 evaluator 选择 keep/drop、Owner、范围或修复方向；不得从 `source_conclusion` 推断是否接受 span，或在缺少 Finalizer explicit index + exact final claim 时自动投影。
