# Word Requirement Extraction Reviewer

Before running, modifying, or evaluating this capability, read `references/product-principles.md`, `references/pi-native-semantic-contract.md`, and `references/pi-native-runtime-contract.md` in full. Treat any conflicting implementation or benchmark result as invalid.

## Workflow

1. Keep the mature single-prompt output as the upstream first judgment.
2. Build an answer-free `xique.word-requirement-review.packet.v1` packet containing the complete immutable source, candidate provenance, and `initialRanges`. Optional Word structure evidence may contain only mechanically extracted, source-bound layout facts.
3. Call `review_word_requirement_extraction_candidate_pi_native` exactly once with the packet path.
4. Report final ranges, patch, degraded state, all three provider calls, Token usage, latency, model identities, Prompt/input hashes, run registry, provisional decision, Witness challenges, final decision, and validator failure.

The active route is one Pi Agent loop with a fixed `GLM provisional -> Doubao 2.0 Pro Witness -> same GLM final delta` sequence. The first GLM tool call submits one complete `provisional_selection` and returns a Harness review packet without terminating the loop. The second GLM call runs in a fresh deterministic neutral-replay provider context built from the original immutable user input plus the normalized provisional submission and Harness review packet; historical assistant/toolResult roles and tool-call IDs are not replayed. Witness independently returns one strict direct-JSON object with two required arrays: `remove_from_provisional` contains zero to three independent counterexample cards and `add_to_provisional` contains zero or one; an empty array is `[]`. Direction is mechanically mapped to internal exclude/select and is not a model field. Field names, card count/order, and supporting-block count carry no authority, and the Witness cannot override the Finalizer. Each active card targets exactly one complete canonical block, carries one `source_conclusion`, and cites 1-8 supporting focus blocks; block-internal text slices and multi-block targets are forbidden by the Witness Prompt. Witness applies the shared controlling-predicate gate and whole-block survivor veto, then runs one global tournament across affirmative exclusion mechanisms and source-proven peer-bounded partitions; the same remedy/price/proof cluster cannot consume multiple card slots. Both roles must exhaust every proposition, alternative trigger, and tail clause instead of using a block-level dominant-purpose shortcut. Recovery must stop only the preceding hard-root projection that still crosses the recovered module; heading closure stops at a source-proven same-level or higher sibling/root; and a Witness add inside a provisional hard-root projection must first use source-grounded `owner_boundary` evidence instead of an atom-content exception. This bounded capacity does not change the source-quote limits, provider-call count, or Harness semantic boundary. A Witness source conclusion should remain one compact sentence, with roughly 192 Chinese characters as an advisory target rather than a local schema limit; the hard resource bound is the single 2400-token Witness output cap. A remove card requires an affirmative exclusion predicate in the target source plus self-falsification against every independent proposition in the target; repetition, redundancy, coverage elsewhere, or a shorter/neater result alone cannot authorize it. The second GLM tool call is the only publishable semantic decision. It freezes the normalized provisional block-ID set as `S0`, performs full selected/excluded closure with the same controlling-predicate gate, and submits only sparse per-run `remove_ranges` / `add_ranges`; the Harness alone derives `S=(S0-Δ-)∪Δ+` and compact final ranges. It cannot regenerate a second full selection from a new chapter summary. The symmetric fixed point and projection checksum validate that delta so typed ranges cannot cross an adjudicated hole or omit an adjudicated survivor; this adds no ledger or call. Finalizer reasons are structurally bounded to 1200 owner characters; residual reason targets 2400 characters and has an 8000-character hard maximum. Over-budget reasons fail closed and are never silently truncated.

Prompt loading and evidence presentation are role-specific. Finalizer receives only the Pi-native semantic contract plus `finalizer.md`; its exact field permissions and two-turn sequence are also supplied by the dynamic `TERMINAL_CONTRACT` and tool schema. The complete Pi-native runtime contract remains Harness/governance truth and stays in the capability hash, but is not concatenated into either model system prompt because its Witness transport, focus, trace, failure, and budget rules are not Finalizer semantics. Witness receives only the self-contained `witness.md` plus the current run's bounded source, mechanical target authorization, all typed hard-root claims, bounded provisional `owner_reason` / `residual_reason` under `UNTRUSTED_PROVISIONAL_RATIONALE`, and exact JSON schema. Physical and semantic order is source → authorization/typed claims → untrusted rationale → unified enumerate/rank; no candidate may be generated before rationale is read. Global ranking is `root contradiction > typed/rationale/source exact contradiction > strongest singleton falsifier`. Every `source_conclusion` must still be independently proved from visible source focus.

`REVIEW_FOCUS_SOURCE` is serialized first. Its `source_ordered_blocks` array contains every deduplicated visible block exactly once in strictly increasing `block_id` order, without provisional state, target permission, or root projection fields. The Harness then serializes `MECHANICAL_TARGET_AUTHORIZATION.remove_from_provisional|add_to_provisional`, whose contiguous ranges are the sole target-address authority, followed by `PROVISIONAL_HARD_ROOT_CLAIMS`, which includes projected and no-projection claims only as typed support, and finally `UNTRUSTED_PROVISIONAL_RATIONALE`. The rationale line has a deterministic 55,272-serialized-character maximum: each accepted normalized reason is additionally bounded in UTF-16 code units, each code unit reserves up to six JSON characters, and the fixed object envelope plus marker are included. Source/auth/claims and rationale share a 190,000-serialized-character input budget; the nominal 180,000-character focus cap is reduced only when the actual rationale line would exceed that combined budget. Rationale semantics/content never selects focus; only its serialized length may mechanically reduce the effective focus budget. Root and non-EOF exit ±2 source windows are visible for both claim classes; only projected claims participate in projection overlap, unclaimed exclusion, and final consistency. Every selected island is fully exposed when the effective block/character budget permits. If it does not, the Harness rotates across all selected islands in deterministic breadth-first midpoint order so large early islands cannot starve later islands; this ordering reads no source meaning and grants no semantic priority.

Each Finalizer turn must contain exactly one valid `submit_final_selection`, which is the sole authoritative output. The tool name stays stable, but the Harness exposes a phase-specific provider schema: the first accepts only `submission_kind=provisional_selection`, complete `run_selections`, and `run_deltas=[]`; the second accepts only `submission_kind=final_delta`, `run_selections=[]`, and changed `run_deltas`. Before the second call, authoritative `ACTIVE_FINALIZER_PHASE=final_delta` and `THIS_IS_FINAL_PROVIDER_CALL=1` markers are placed outside the untrusted provisional/review packet. The Prompt still requires no prose. If a provider nevertheless emits ordinary text in the same turn, the Harness does not parse, interpret, or use it; it records only the exact concatenated text character count and SHA-256 as auxiliary trace and marks `forwarded=false`. Before the second Finalizer model context, the Harness validates the provisional tool-call/tool-result pair, then removes the historical assistant/toolResult roles, tool-call ID, and auxiliary text and appends the normalized provisional submission plus review packet to the original user input. Finalizer trace stores raw tool arguments, normalized structured submissions, and auxiliary-text metadata; it does not persist the raw Finalizer assistant message. Thinking content, an unknown or additional tool call, truncation, or invalid tool arguments still fail closed.

Final publication requires exactly two Finalizer calls and one Witness call, valid schemas and ranges, and:

```text
FINAL_SELECTION ∩ FINAL_HARD_ROOT_PROJECTION = ∅
```

After provisional submission, the Harness exposes any typed selection/claim overlap as `mechanical_contract_blockers.selection_intersects_hard_claim_ranges`. Treat it like compiler feedback: it identifies an inconsistent address intersection but does not decide whether source requires changing the selection, the claim exit, or both. The Finalizer must resolve it in the second typed submission; code never resolves it semantically.

Any provider, timeout, abort, capacity, JSON, turn-shape, schema, nonexistent source address, call-count, or final-consistency failure preserves the upstream Candidate unchanged and marks the review degraded. Empty Witness arrays must be `[]`. Missing arrays or card fields, `null`, string `"null"`, empty card objects, old exclude/select/`kind=none`/primary/secondary fields, `attacked_premise`, direction fields, and extra fields all fail closed; there is no coercion or partial-JSON repair. Witness raw trace contains the exact assistant JSON text, while normalized Witness trace contains the parsed object only after native `JSON.parse` succeeds. Each card is independently checked against visible `source_ordered_blocks`, its corresponding `MECHANICAL_TARGET_AUTHORIZATION` contiguous range, and `AUDIT_UNIVERSE`; source blocks outside authorization may support a card but can never be its target. A dynamically unauthorized card is rejected trace-only with its internal lane and stable zero-based card index, while other valid cards may continue under `partial` coverage. If a Finalizer encodes EOF as `exit_block_id_exclusive = terminalBlockId + 1`, the Harness mechanically normalizes that one-past-end address to `null`; it does not infer that a hard root is valid or that its Owner reaches EOF, and every other nonexistent or invalid exit still fails closed. For a provisional selection range, the Harness may mechanically discard ordinary `OUT` spill only when the remaining addresses are non-empty and form exactly one continuous island inside the declared run; final deltas never receive spill trimming and must remain wholly inside their declared run. All-`OUT`, cross-run, unavailable-block, multi-island, wrong-provisional-membership, duplicate-block, duplicate-run, or empty per-run deltas fail closed. There is no retry, fourth call, best-of-N, voting, block ledger, keyword scan, or code-side semantic repair.

## Scope

- For a non-empty Candidate, `AUDIT_UNIVERSE` is exactly the Candidate address set. This version can repair false-positive membership and scope precision, but cannot claim arbitrary remote `OUT` omission repair.
- For an empty Candidate, `AUDIT_UNIVERSE` mechanically expands to the complete source so the Agent can repair a common-mode false-null.
- `RUN_REGISTRY` is created only from address continuity. It carries no Owner, confidence, or expected-answer signal.
- Different canonical `block_id` values are mechanically separable output atoms. Heading/body closure remains a model judgment.

## Boundaries

- Do not parse DOCX, run the upstream Candidate, or access another repository from the Extension.
- Do not provide expected answers, Production output, historical winners, evaluator labels, case-specific hints, or answer-derived structure evidence.
- Keep engineering, goods, and services under the same semantic contract. Do not branch on project, industry, template, case ID, source hash, or known answer.
- Code may provide only Pi harness adaptation and atomic mechanical tools: packet/hash validation, canonical addresses, answer-free layout, schema, context/call/Token/timeout budgets, bounded focus, set consistency, patching, and trace. It must not interpret source wording or decide Owner, membership, keep/drop, or repair direction.

## Runtime

Finalizer uses `pi-requirement-release-glm/glm-5.2`. Supply `PI_REQUIREMENT_RELEASE_API_KEY`; optionally override `PI_REQUIREMENT_RELEASE_BASE_URL`.

Witness uses `pi-requirement-reviewer-doubao/doubao-seed-2-0-pro-260215`. Supply `PI_REQUIREMENT_REVIEWER_API_KEY`; optionally override `PI_REQUIREMENT_REVIEWER_BASE_URL`.

`Content-Type: application/json` serializes the Doubao request body. Witness runs with `tools=[]`; the provider payload removes tools, tool choice, parallel tool calls, and reasoning effort, uses `response_format: {"type":"json_object"}`, and explicitly sends the frozen runtime `thinkingMode`. The default is `disabled`. A predeclared sealed A/B runner may set `witnessRuntime.thinkingMode=enabled` once for the whole run before the first semantic call; the choice must not depend on case identity, source meaning, provisional output, evaluator labels, prior results, or failure recovery. Enabling thinking changes only this provider runtime profile: model, source/focus, Prompt, exact `PiNativeSemanticWitnessSchema`, one-call Witness limit, fixed `2 Finalizer + 1 Witness` sequence, no-retry rule, and the 2400-token provider-visible JSON response limit remain unchanged. Provider-reported hidden reasoning is accounted separately: the run reasoning-token limit is 1000 in the default disabled profile and 6000 in the explicit enabled profile, while the existing 20000-token total run output limit still applies. Disabled mode rejects any thinking block. Enabled mode permits at most one thinking block plus exactly one JSON text block; Harness records only mode, block count, character count, and `forwarded=false`, and neither persists nor forwards the thinking content. The complete JSON text is still enforced locally after native `JSON.parse` with TypeBox plus per-card cross-field validation. Provider JSON mode and optional thinking are transport/runtime assistance, not semantic authority or replacements for the local contract.
